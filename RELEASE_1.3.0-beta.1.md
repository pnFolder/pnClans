# v1.3.0-beta.1 — Антифарм очков и расширенное управление кланами

`v1.3.0-beta.1` — крупное функциональное обновление pnClans, сфокусированное на защите клановых очков от PvP-фарма и на расширении инструментов администратора.

Теперь начисление очков проходит через полноценную anti-farm систему, а основные операции с очками, товарами магазина и участниками клана можно выполнять непосредственно командами администратора без ручного редактирования данных.

## Главное

- Полноценный PvP anti-farm для клановых очков.
- Новый централизованный `points.yml`.
- История и rollback операций с очками.
- Расширенная `/clan admin points`.
- Управление магазином через `/clan admin shop`.
- Управление участниками через `/clan admin member`.
- Публичные Bukkit-события anti-farm для интеграций.
- Поддержка JSON и SQLite.

## Anti-farm очков

Обычные PvP-убийства теперь проходят через единый anti-farm pipeline до начисления награды.

Доступны отдельные настраиваемые проверки:

- убийство участника своего клана;
- повторное убийство одной и той же жертвы;
- cooldown между повторными убийствами;
- дневной лимит убийств одной жертвы;
- двусторонний лимит пары игроков `A ↔ B`;
- опциональная проверка одинакового IP;
- минимальное игровое время жертвы;
- минимальный возраст аккаунта на сервере;
- diminishing returns для повторного фарма;
- дневной лимит очков для игрока;
- дневной лимит очков для клана.

Каждую проверку можно включать и отключать отдельно в `points.yml`.

Anti-farm tracking сохраняется между перезапусками сервера.

## API и события

Добавлены публичные Bukkit-события:

- `ClanPointsAntiFarmPreCheckEvent`;
- `ClanPointsAntiFarmResultEvent`.

Через них сторонние плагины могут интегрироваться в систему начисления: отменять обработку, обходить встроенные проверки или изменять итоговую награду.

## История и управление очками

История операций с Clan Points стала значительно подробнее.

Для транзакций сохраняются:

- уникальный ID;
- инициатор операции;
- цель;
- причина;
- изменение баланса;
- связь с исходной транзакцией при rollback.

Администратору доступны операции просмотра, добавления, удаления, установки и сброса очков, просмотр истории, rollback конкретной транзакции, просмотр anti-farm tracking и его очистка.

## Управление магазином

Расширена `/clan admin shop`.

Теперь из игры можно:

- просматривать список товаров;
- получать подробную информацию о товаре;
- создавать товар;
- добавлять предмет прямо из руки через `addhand`;
- удалять товар;
- менять цену;
- менять категорию;
- менять слот;
- клонировать товар.

`addhand` сохраняет сериализованный Bukkit `ItemStack`, поэтому при выдаче сохраняются метаданные предмета, а не только его базовый Material.

## Управление участниками

Расширена `/clan admin member`.

Доступны:

- список участников;
- информация об участнике;
- принудительное добавление;
- удаление;
- изменение роли;
- безопасная передача лидерства.

Операции используют существующую логику и события pnClans, а не обходят сервисы прямым изменением данных.

## Хранилище

Новые anti-farm данные и расширенная история транзакций поддерживаются в обоих хранилищах pnClans:

- JSON;
- SQLite.

## Обновления и сборки

Система релизов переведена на канонические имена JAR:

- `pnClans-1.3.0-beta.1-paper-java21.jar`;
- `pnClans-1.3.0-beta.1-paper-java25.jar`.

AutoUpdater определяет канал обновления по SemVer-тегу GitHub:

- `X.Y.Z` → STABLE;
- `X.Y.Z-beta.N` → BETA;
- `X.Y.Z-alpha.N` → ALPHA;
- `X.Y.Z-rc.N` → RC.

GitHub-флаг `Pre-release` не используется для определения канала.

## Важно

> Если включена проверка `sameIp`, сервер должен получать реальные IP игроков. При использовании Velocity или BungeeCord необходимо корректно настроить forwarding. В противном случае разные игроки могут определяться как подключённые с одного IP.

Это beta-версия по SemVer-тегу и предназначена для полноценного тестирования новых anti-farm и административных возможностей перед дальнейшим продвижением ветки `1.3.0`.
